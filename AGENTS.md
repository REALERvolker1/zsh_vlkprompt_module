# zsh-autocomplete-rs

A rewrite of the `zsh-autocomplete` plugin to correct several wrongs and
shortcomings of the original plugin

# Code style

Rust `no-std`, no-alloc. This is a FFI-based plugin.

All memory must be stack-allocated. If it is impossible to write a routine
without a heap allocation, simply create a dummy buffer and move on. Explicitly
mention that place in your output.

ZSH FFI bindings are exported via the `zsh-sys` crate, more specifically in the very large autogenerated file
`./vendored/zsh-module-rs/zsh-sys/src/bindings.rs`.
There are also some commented-out definitions for C macros found in the zsh
source code that you may need to know in order to implement some things properly.
Do not use `./vendored/zsh-module-rs/zsh-module` in generated code, it is _very_ incomplete. You
may read files in it to learn more about zsh modules, but you may not import, use, or modify it.

You may read `./gitignored/zsh/Src/Modules/example.c` or any other `.c` files located
in that directory to learn how zsh modules work.

# FORBIDDEN

## DO NOT USE MALLOC UNDER ANY CIRCUMSTANCES.

- **FORBIDDEN FUNCTIONS:** malloc, realloc, reallocarray, calloc, zalloc, zstrdup, zshcalloc, zrealloc, zreallocarray, etc.
- **DO NOT HIDE ALLOCATION INSIDE OF FUNCTIONS**
- **DO NOT ABUSE HEAP-ALLOCATED TYPES** (Ex. Hiding unrelated data inside of hash tables, doing anything with linkedlists, etc.)
- Do not use `core::fmt`, use the dedicated printing functions in `printing.rs`
